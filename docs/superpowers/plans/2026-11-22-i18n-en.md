# English UI language: implementation plan

> **For agents:** work task by task; steps are marked `- [ ]`. Skill: superpowers:executing-plans.

**Goal:** the FPGA SIM interface is available in English; the Russian interface of current students does not change.

**Design:** the `web/src/i18n` module picks the language once at load (URL → stored choice →
browser language list → Russian). The dictionary `en.json` sits next to `ru.json`. Changing the language
writes the choice and reloads the page. Per-language texts in parts, diagnostics and board files are
an object `{ru, en}` (`$defs/text` in `spec/part.schema.json`). `localized()` picks the string.

**Tools:** React, TypeScript, Vitest, Playwright, Python 3.12 (server), JSON Schema.

**Design document:** `docs/superpowers/specs/2026-11-22-i18n-en-design.md` — read it together with this plan.

## General requirements

- Languages: `ru`, `en`. Number and date locales: `ru-RU`, `en-US`.
- URL parameter `lang`, values `ru` | `en`; a value found there is stored as the choice.
- Storage key of the choice: `fpgasim.language` in `localStorage`.
- Neither `ru*` nor `en*` in `navigator.languages` — Russian.
- UI strings only in `ru.json` and `en.json`. Exception: the language names "Русский"
  and "English" in the switch (each written in its own language).
- Expectations of existing tests do not change, except `server/tests/test_api.py:160`
  (`device` becomes an object — a consequence of the format).
- Colors are theme variables; a choice list is `Choice` or a shadcn menu, not `<select>`.
- Commits: "web: …", "server: …", "formats: …", "docs: …", with the `Co-Authored-By` and `Claude-Session`
  signature from the session.

## What to check in review

1. A `lv`/`uk` browser with no `en` and no `ru` in the list — Russian (test in task 1).
2. Typing in the editor and switching the language at once — the edit is not lost (test in task 5).
3. A key or a `{…}` placeholder exists in one dictionary and not in the other (test in task 2).
4. An `{ru, en}` object passed into the `{device}` placeholder — the text is shown, not JSON (test in task 1).
5. Old interface with the new server during deployment — the `DEVICE_NOT_MODELED` notice does not break
   the page (check in task 4, the step about deployment order).

- Test: `web/src/i18n/language.test.ts`

**Interfaces (produces):**
- `type Language = "ru" | "en"`
- `pickLanguage(search: string, stored: string | null, browser: readonly string[]): Language`
- `language: Language` — chosen when the `i18n` module loads
- `setLanguage(lang: Language): Promise<void>` — writes the choice, waits for `beforeLanguageChange`, reloads
- `onBeforeLanguageChange(fn: () => Promise<void>): void` — registration (done by `actions.ts`, task 5)
- `localized(text: Record<string, string> | string | undefined): string` — current language, else `ru`;
  a string is returned as is, `undefined` → `""`
- `numberLocale(): "ru-RU" | "en-US"`
- `fill()`: an object value with a `ru` field is substituted through `localized`

- [ ] Test `pickLanguage`: `("?lang=en", "ru", ["ru"])` → `en`; `("", "en", ["ru"])` → `en`;
  `("", null, ["lv"])` → `ru`; `("", null, ["lv","en","ru"])` → `en`; `("", null, ["uk","ru","en"])` → `ru`;
  `("", null, ["en-GB"])` → `en`; `("?lang=de", null, ["ru-RU"])` → `ru`; a stored `"xx"` is ignored.
- [ ] Test `localized`: `{ru:"а",en:"b"}` with `en` → `b`; `{ru:"а"}` with `en` → `а`; `"x"` → `x`.
- [ ] Test `fill("{d}", {d:{ru:"а",en:"b"}})` gives text, not JSON.
- [ ] Run `cd web && npx vitest run src/i18n` — the tests fail.

  a `lang` found in the URL is stored;
  `document.documentElement.lang = language`. `t`/`tOr`: dictionary of the language → `ru.json` → key.
  `localized` and `fill` read the current language; for tests, `setLanguageForTests(lang)` in `language.ts`.
- [ ] `test-setup.ts` sets `ru`; `vite.config.ts`: `setupFiles: ["src/test-setup.ts"]`.
